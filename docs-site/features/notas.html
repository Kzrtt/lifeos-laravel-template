Notas

Registros de contexto em markdown — pensamentos, leituras, pesquisas — ligados a quantos projetos fizerem sentido.

✅ implementadomarkdownmermaidpdfN:N

O problema

Guardar contexto que não é tarefa nem evento: análises de leitura, lembranças, documentação. Uma nota não tem ciclo de vida — é só um registro.

As regras

  1. Uma nota tem nome, tipos (vocabulário nota_tipo: Lembranças, Análise de Leitura, Pensamentos, Conclusões, Úteis, Faculdade, Vida, Pesquisa, Programação, Pessoal, Relato, Documentação), data opcional e conteúdo em markdown.
  2. O vínculo com projetos é N:N: zero, um ou vários. Ao atualizar, a lista de projetos enviada substitui o conjunto inteiro.
  3. Excluir uma nota limpa seus vínculos; excluir um projeto remove só o vínculo daquela nota com ele — a nota permanece.
  4. A data é a data real do conteúdo, não a de criação; a lista ordena por data decrescente (sem data por último) e usa a criação só como desempate.
  5. Diagramas Mermaid: um bloco ```mermaid vira diagrama na tela (hub, notas, tarefas, pré-visualização) e no PDF. Sintaxe incompleta deixa o bloco como código, sem erro.
  6. Exportar PDF: impressão nativa do navegador; o PDF espera os diagramas renderizarem e os desenha no tema claro.
  7. Cada nota tem link próprio (notas.html?nota=<id>) que abre direto na leitura em tela cheia; se a nota não estiver no cache local, a página busca de novo antes de desistir.
  8. O ↻ do hub é um reload mestre: além do cache do hub, preenche os das páginas de detalhe.
